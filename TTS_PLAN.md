# План: Озвучка текста в MoFrame

## Анализ задачи

**Что:** Автоматическая озвучка текста из комиксов при конвертации в видео.
**Зачем:** Видео получается "немым", текст не озвучивается. Озвучка сделает контент доступнее и живее.
**Для кого:** Пользователи MoFrame, создающие видео из комиксов.

## Текущая архитектура

```
Комикс → Loader → PanelDetector → Editor → Renderer → MP4
                     ↑
              React Canvas UI
```

## Целевая архитектура

```
Комикс → Loader → PanelDetector → [OCR Module] → Editor + Текст → Renderer → MP4 + Аудио
                     ↑                                  ↑
              React Canvas UI                    TTS Preview
```

## Техническое решение

### 1. OCR (Извлечение текста)

**Вариант A: Tesseract + pytesseract** ⭐ Рекомендуется
- Плюсы: локальный, бесплатный, много языков, хорошо документирован
- Минусы: требует установки tesseract
- Сложность: средняя

**Вариант B: EasyOCR**
- Плюсы: deep learning, лучше для рукописного текста
- Минусы: тяжёлые модели, медленнее
- Сложность: выше

**Вариант C: macOS Live Text (Vision API)**
- Плюсы: нативный, точный
- Минусы: только macOS, сложно интегрировать
- Сложность: высокая

**Решение:** Начать с **Tesseract + pytesseract**.

### 2. Определение речевых пузырей

**Проблема:** Нужно отличать текст в речевых пузырях от звуковых эффектов ("BOOM!", "POW!") и от описаний.

**Решение (этап 1):**
- Извлекать весь текст из панели
- Позволить пользователю редактировать/фильтровать в UI
- Не пытаться "умно" классифицировать на первом этапе

**Решение (этап 2):**
- ML-классификация типов текста (speech, sfx, caption)
- Или простые эвристики (короткий капс = sfx, длинный = речь)

### 3. TTS (Text-to-Speech)

**Вариант A: macOS `say`** ⭐ Быстрый старт
- Плюсы: уже есть в системе, русский/английский, просто вызвать subprocess
- Минусы: macOS only, качество "роботное"
- Использование: `say -v Yuri "Текст" -o audio.aiff`

**Вариант B: gTTS (Google)**
- Плюсы: бесплатный, хорошее качество
- Минусы: требует интернет, не для коммерческого использования
- Сложность: низкая

**Вариант C: Edge-TTS (Microsoft)**
- Плюсы: бесплатный, отличное качество, русский, английский
- Минусы: требует интернет
- Сложность: низкая

**Вариант D: ElevenLabs (sag skill)**
- Плюсы: высокое качество, много голосов
- Минусы: платный API, нужен ключ
- Сложность: средняя

**Вариант E: sherpa-onnx-tts**
- Плюсы: локальный, оффлайн
- Минусы: нужно скачать модели, качество среднее
- Сложность: выше

**Решение:**
- **Этап 1:** `say` для macOS (быстро, бесплатно)
- **Этап 2:** Edge-TTS (лучшее качество)
- **Этап 3:** ElevenLabs (премиум)

### 4. Интеграция аудио в видео

**Инструмент:** FFmpeg (уже используется для рендера)

**Pipeline:**
1. Для каждой панели:
   - Извлечь текст (OCR)
   - Сгенерировать аудио (TTS)
   - Определить длительность аудио
   - Синхронизировать с видео (панель показывается ≥ длительности аудио)
2. Склеить аудио-сегменты с паузами между ними
3. Наложить на видео

## Пошаговый план реализации

### Этап 1: Исследование и прототип (4-6 часов)
- [ ] Установить Tesseract (`brew install tesseract`)
- [ ] Установить pytesseract (`pip install pytesseract`)
- [ ] Прототип OCR на тестовом комиксе
- [ ] Прототип TTS через `say` или Edge-TTS
- [ ] Проверить синхронизацию аудио+видео через FFmpeg

### Этап 2: OCR модуль (6-8 часов)
- [ ] Создать `core/ocr.py` — извлечение текста из панели
- [ ] Функция: `extract_text(image) -> List[TextBlock]`
- [ ] TextBlock: {text, bbox, confidence}
- [ ] Тесты для OCR

### Этап 3: TTS модуль (6-8 часов)
- [ ] Создать `core/tts.py` — генерация аудио
- [ ] Абстракция: `TTSProvider` с методом `synthesize(text, lang) -> audio_bytes`
- [ ] Реализации: `SayTTSProvider`, `EdgeTTSProvider`
- [ ] Кэширование (не генерировать повторно)
- [ ] Тесты для TTS

### Этап 4: Аудио пайплайн (8-10 часов)
- [ ] Создать `core/audio_pipeline.py`
- [ ] Синхронизация: для каждой панели определить длительность
- [ ] Если аудио длиннее панели — растянуть панель или обрезать аудио
- [ ] Паузы между панелями (настраиваемые)
- [ ] Нормализация громкости
- [ ] Микширование с фоновой музыкой (если будет)
- [ ] Интеграция с renderer.py

### Этап 5: UI интеграция (8-12 часов)
- [ ] Добавить toggle "Озвучка" в Step 4 (Render)
- [ ] Выбор провайдера TTS (say / Edge / ElevenLabs)
- [ ] Выбор голоса/языка
- [ ] Предпрослушивание перед рендером
- [ ] Редактирование распознанного текста (Step 3)
- [ ] Отображение текста под панелью в preview

### Этап 6: Тестирование и полировка (6-8 часов)
- [ ] Тест на русском комиксе
- [ ] Тест на английском комиксе
- [ ] Тест с разными шрифтами
- [ ] Обработка ошибок (нет текста, OCR не справился)
- [ ] Оптимизация скорости

## Риски и вопросы

1. **Качество OCR:** шрифты комиксов могут быть нестандартными, текст наклонный, искривлённый. Может потребоваться fine-tuning модели.
2. **Качество TTS:** `say` — роботный, Edge-TTS — лучше, ElevenLabs — дорого. Какой баланс?
3. **Синхронизация:** если текст длинный, аудио может быть длиннее длительности панели. Нужно ли растягивать видео?
4. **Мультиязычность:** комикс может быть на разных языках. Как определять язык?
5. **Производительность:** OCR + TTS для каждой панели = медленно. Нужно кэширование и возможно async.
6. **Лицензии:** gTTS не для коммерции. Edge-TTS — ?

## Рекомендации по приоритетам

1. OCR через Tesseract
2. TTS через `say` (macOS) или Edge-TTS
3. Без UI редактирования текста (только toggle on/off)
4. Автоматическая синхронизация (панель длится = max(время, аудио))
